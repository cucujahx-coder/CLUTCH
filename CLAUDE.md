# CLUTCH — задачи как чаты

Мобильный task-менеджер, где каждая задача — это чат с ИИ. Задачу можно просто закрыть галочкой, а можно «толкать вперёд» перепиской. Большие задачи разбиваются на шаги (проекты), в списке виден только текущий шаг.

День строится в три приёма: накидал в **Inbox** → ИИ собрал **План** на сегодня → разобрал колодой в **Фокусе**.

Живёт на GitHub Pages как PWA: https://cucujahx-coder.github.io/CLUTCH/

## Стек и запуск

- Vite + React 18, один файл `src/App.jsx` (~600 строк), стили inline + один `<style>` с CSS-анимациями.
- Без UI-библиотек, без Tailwind, без роутера. Все иконки — inline SVG через компонент `Ic`.
- `npm install && npm run dev` — локально. `npm run build` — сборка в `dist/`.
- Деплой: `git push` в `main` → `.github/workflows/deploy.yml` собирает и выкладывает на Pages. `base: "/CLUTCH/"` в `vite.config.js` обязан совпадать с именем репозитория.
- Проверка синтаксиса без сборки: `npx esbuild src/App.jsx --loader:.jsx=jsx --log-level=error > /dev/null`.

## Модель данных

Один массив `tasks` в state, сохраняется целиком в `localStorage` под ключом `clutch:v5` (при несовместимых изменениях схемы — поднять версию ключа). `OLD_KEYS` — список прежних ключей: если новый пуст, `load()` один раз перечитывает старый и переписывает в новый. Добавляя следующий ключ, не забудь дописать предыдущий в этот список, иначе у людей молча пропадут задачи.

```js
{
  id, title,
  due: "YYYY-MM-DD" | null,   // дата; просроченные при загрузке переносятся на сегодня (rollover)
  done: boolean,
  priority: 0 | 1 | 2,        // 0 обычная, 1 важная, 2 срочная — задаётся «!» / «!!» в конце текста
  createdAt,
  doneAt,                     // время выполнения; по нему собирается секция «Выполнено» в Плане
  messages: [{ id, role: "user" | "ai", text }],
  // проекты
  isProject?: true,           // родитель; в «Сегодня» не показывается
  projectId?: string,         // у шага — ссылка на родителя
  order?: number              // порядок шага внутри проекта
}
```

Флаг `done` меняется только через `mark(t, done)` — он же проставляет и обнуляет `doneAt`. Ставить `done` напрямую нельзя, иначе задача не попадёт в «Выполнено».

План дня лежит отдельно, в ключе `clutch:plan`:

```js
{ forDate: "YYYY-MM-DD", items: [{ id, include: boolean }] }
```

`forDate` привязывает план к дню: наступило завтра — `planStale` становится `true`, и вкладка «План» снова предлагает «Спланировать».

`DEMO` (константа наверху файла) — `true` генерирует случайный набор задач при каждом запуске и отключает сохранение. В продакшене `false`.

## Экраны

Сегментированный переключатель в шапке: **Inbox · План · Фокус**. Вкладка — состояние `tab` (0 = Inbox, 1 = План), фокус — отдельный флаг `focus`. Именно `tab`, а не `page`: стилевая константа тоже зовётся `page`, и когда состояние назвали так же, `{...page}` разворачивал число вместо стилей и обнулял весь корневой div.

1. **Inbox** (`inboxList`) — задачи без даты, ещё не попавшие в план. То, что не разобрано.
2. **План** — день, собранный ИИ. Один скролл, сверху вниз: `doneToday` (выполненное сегодня, по `doneAt`), `upcomingList` (будущие даты, дальняя вверху) и сам план у самого низа, у композера. Внутри каждой секции ближайшее к «сейчас» — внизу, под большим пальцем. Заголовок «Сегодня» показывается, только если выше есть хоть одна секция. Выключенная из плана задача остаётся строкой с зачёркнутым названием и кнопкой «+», чтобы вернуть.
3. **Фокус** (`Focus`) — полноэкранная колода, задачи по одной. Свайп вправо — сделано, влево — отложить (спрашиваем «что мешает», ответ уходит в чат задачи), вверх — удалить, тап — открыть чат. Сзади видны две следующие карточки.
4. **Шторка задачи** (`Sheet` + `Task`) — выезжает снизу CSS-keyframes. Шапка: ✕, название (у шага — подпись проекта «N из M»), чекбокс. Чат, над композером чипы: дата, приоритет, «В план», «Разбить на шаги» (для одиночной задачи), «Удалить». У проекта вверху чата чек-лист шагов.

## Ключевые механики

- **Композер** (`Composer`) — один компонент для обоих экранов: скрепка (файлы), поле, микрофон (Web Speech API, ru-RU), который при наличии текста становится кнопкой отправки. На главной у отправки жест: удержание 220 мс превращает плашку в 7 равных пунктов дней недели, палец влево выбирает, отпустил — создал задачу на эту дату (`dateMenu`).
- **Парсер дат** `parseDue` — «завтра», «послезавтра», «через 3 дня», «в пятницу», «12 сентября», «15.10». Регулярки используют lookaround вместо `\b` — `\b` не работает с кириллицей.
- **Выполнение** (`complete`) — всё одновременно за ~150 мс: «призрак» текста взрывается на месте (`ghosts`), 💥 + искры + радиальная и экранная вспышки (`booms`), синтезированный звук хлопка (`pop`, WebAudio, без файлов), вибрация (`tap`). Задача сразу уходит из списка; если это шаг проекта — в тот же слот прилетает следующий с анимацией `landed` (слот стабилен, потому что сортировка идёт по ключу проекта — `anchor(t)`).
- **Undo** — плашка «Выполнено: … — Вернуть» над композером на 5 с (`undo`, `doUndo`).
- **Вибрация** — `navigator.vibrate` на Android; на iPhone трюк со скрытым `<input type="checkbox" switch>` (`iosTick`, работает в Safari 17.4–26.4).
- **Отклик касания** — `.press` сжимает элемент, `.elflash` вспыхивает белым самим элементом (навешивается в `onDown` через `closest(".press, .row-press, .composer")`).
- **Фокус-режим** (`Focus`) — колода поверх всего: `drag` тянет карточку за пальцем, порог 110 px по горизонтали и 120 px вверх. Вправо — `onDone`, влево — карточка «что мешает» с готовыми причинами и своим вариантом (причина уходит в чат задачи, дата двигается на 1–2 дня), вверх — удаление. Счётчик «N из M» считает и задачи, добавленные прямо в фокусе.
- **Проекты** — `makeProject(id, steps)` превращает задачу в проект и создаёт шаги; шаги проекта в списке рисуются стопкой (подложки по числу оставшихся, максимум 2), внутри чекбокса — число оставшихся шагов.

## Точки подключения ИИ

Обе функции наверху файла, обе — заглушки с задержкой. Реальный ключ API в клиент класть нельзя: они должны ходить в серверную функцию (Cloudflare Workers / Vercel), которая уже вызывает модель.

- `askAssistant(task)` → строка ответа. Получает задачу целиком, включая `messages`, `isProject`.
- `askPlan(task)` → массив строк-шагов. Пользователь редактирует план и подтверждает — только тогда создаются шаги.
- `askDayPlan(candidates, forDate)` → `{ items: [{ id, include }] }`. Отбирает задачи на день из `candidates` (не выполнены, не проекты, у проектов — первый открытый шаг, дата ≤ сегодня или пусто). Порядок: срочные, затем шаги проектов, дальше по давности; в план входит не больше `DAY_MAX`. Оценок времени и сложности сознательно нет — пробовали, убрали: модель не может их честно дать, а цифры в интерфейсе выглядят обещанием.

## Дизайн — правила, к которым пришли

- Тёмная палитра как у приложения Claude: фон `#161616`, плашки `#1C1C1C`, линии `#343434`, текст `#EDEDEB`, вторичный `#9A9A96`. Кнопка отправки и отмеченный чекбокс — белые.
- Шрифт **Play** (Google Fonts), размер 17 в списке и поле ввода.
- Всё круглое/овальное: кнопки 44 px, радиус плашек 28, чипы — пилюли.
- Фон — мягкий radial-gradient сверху (`#242424` → `#111111`), им же залит фокус-режим. Тени допустимы там, где нужно оторвать слой от фона: карточка фокуса и шторка задачи. Плоские элементы списка теней по-прежнему не имеют.
- Строки задач без фона и обводки; фон и рамку имеют только плашки шагов проектов (чтобы читалась стопка) и композер.
- Сетка: композер и плашки имеют одинаковый внутренний отступ (11 + 1 рамка), поэтому чекбоксы стоят ровно в колонке с микрофоном. Любая правка размеров кнопок в композере должна зеркалиться в `box`.
- Приоритет — только цвет кольца чекбокса (оранжевый / красный), без бейджей и полосок.
- Нет: типов задач, превью чатов в строке, заголовков дат в списке. Делали и убирали по просьбе владельца — не возвращать без явного запроса.
- Секции «Выполнено» и «Предстоящие» живут только во вкладке «План». В Inbox и в фокусе их нет и быть не должно.

## Как вносить изменения

- Правки точечные, через `str_replace`, не переписывать файл целиком.
- После любой правки — esbuild-проверка (команда выше) и проверка, что все идентификаторы объявлены: при замене больших блоков уже дважды выпадали `STATUS`, `pageRef`, `PRESS_CSS`.
- Все стили — константы в конце файла (`page`, `row`, `box`, `composer`, `inBtn`, `roundBtn`, `chip`, `bubble`, `toast`, `undoBtn`, `cardBox`, `dateItem`). Менять там, а не inline.
- Анимации — в `PRESS_CSS`. Тайминги под 150–300 мс, владелец предпочитает резкие.
- Новые фичи сначала предлагать вариантами (3–5), реализовывать выбранный.
