# Серверная часть чата

Приложение — статика на GitHub Pages, а ключ Anthropic в статику класть нельзя: бандл публичный, ключ вынут за минуту. Поэтому чат ходит не в API напрямую, а сюда: воркер хранит ключ и системный промпт и сам вызывает модель.

Клиент присылает только данные задачи — название, срок, шаги, переписку. Промпт, модель и лимиты задаёт воркер, из тела запроса они не подменяются. Значит адрес воркера, который виден в бандле, нельзя использовать как универсальный прокси к модели за твой счёт.

## Развернуть

Нужен аккаунт Cloudflare — бесплатного тарифа хватает с запасом (100 000 запросов в день).

```bash
cd worker && npx --yes wrangler login
```

```bash
cd worker && npx --yes wrangler secret put ANTHROPIC_API_KEY
```

Ключ вводится в консоли и хранится у Cloudflare — в репозиторий он не попадает.

```bash
cd worker && npx --yes wrangler deploy
```

В конце команда напечатает адрес вида `https://clutch-chat.ТВОЙ-САБДОМЕН.workers.dev`. Его надо вписать в `app.js`:

```js
const API='https://clutch-chat.ТВОЙ-САБДОМЕН.workers.dev';
```

Пока `API` пустая строка, чат отвечает локальной заглушкой — приложение остаётся рабочим без сервера.

## Свой домен вместо workers.dev

`workers.dev` — бесплатный служебный домен Cloudflare, на нём массово размещают фишинг, поэтому он попадает в блок-листы операторов и провайдеров. Симптом: на одной сети чат работает, на другой Safari пишет «Load failed», а сам адрес воркера не открывается даже в браузере. Кэш и настройки приложения тут ни при чём — запрос не уходит из сети.

Лечится привязкой своего домена. Нужен домен, чьи NS-серверы указывают на Cloudflare (домен добавлен в аккаунт как сайт).

1. Панель Cloudflare → Workers & Pages → выбрать воркер → Settings → Domains & Routes → Add → Custom Domain.
2. Ввести поддомен, например `chat.твойдомен.ру`. DNS-запись Cloudflare создаст сам, сертификат выпустит за пару минут.
3. Вписать новый адрес в `API` в `app.js`.
4. Поддомен, с которого приложение обращается к воркеру, менять не нужно: в `ALLOW` перечислены origin **приложения** (`cucujahx-coder.github.io`), а не адрес самого воркера.

Проверить, что домен поднялся: открыть его в браузере — воркер ответит `Only POST`.

## Проверить

```bash
npm run test:worker
```

Тест подменяет вызов к Anthropic и проверяет сборку запроса, отсев чужих origin, обработку отказа модели и ошибок апстрима. Настоящий ключ для него не нужен.

## Из чего состоит

- `worker.js` — приём запроса, проверки, вызов Anthropic, пересборка потока SSE в свой формат.
- `prompt.js` — сборка системного промта из четырёх блоков и календарь. Источник правды для текста — `PROMPT.md` рядом.
- `PROMPT.md` — сам промт и описание блоков. Правишь промт — правь оба файла вместе.
- `worker.test.mjs` — проверки без настоящего ключа: поток Anthropic подменяется.

## Настройки

Всё наверху `worker.js`:

- `DEFAULT_MODEL` — `claude-sonnet-5`; переопределяется переменной окружения `CHAT_MODEL`.
- `EFFORT` — `low`: чат должен отвечать быстро. Если ответы кажутся поверхностными, поднять до `medium` или `high`.
- `MAX_TOKENS` — 2048. Реплики короткие, но с запасом, чтобы ответ не обрывался на полуслове.
- `ALLOW` — список origin, которым разрешено обращаться. Держать конкретным: `*` означает, что твой ключ обслуживает любой сайт в интернете.
- `SYSTEM` — системный промпт. Правится здесь, а не в приложении.

Расширенное мышление не настраивается: на Claude Opus 5 оно включено по умолчанию, и параметр `thinking` намеренно не передаётся.

## Защита от чужих запросов

Отсев по `Origin` останавливает обращения из браузера с чужих сайтов, но не из curl — заголовок подделывается. Если адрес воркера куда-то утечёт, включи Rate Limiting в панели Cloudflare (бесплатно): правило на путь воркера, например 60 запросов в минуту с адреса.
